# 待改善清單

程式跟規格（`openspec/specs/`）不一致的地方、當初將就的做法，以及還沒決定的設計問題。

- 處理某一項時，在 commit 訊息註明編號（例如「B2」），做完從清單刪掉
- 新增項目時接著編號，不重複使用已刪除的編號
- 來源：2026-10-01 Phase 1 規則考古（使用者逐條確認），以及建立 `GLOSSARY.md` 時延後的決定

## 程式與規格不一致

### B1 旅程天數寫死成 6 天
- 現況：天數按鈕、表單的天數選項、路線顏色都寫死 6 天；地圖路線用「Day 6」判斷最後一天不回飯店；`check-data.js` 從天數按鈕讀出可排的天數
- 出處：`index.html:105-110`、`index.html:418-423`、`app.js:1384`、`app.js:1389`、`tools/check-data.js:22`
- 規格：itinerary「旅程天數由旅程決定」、map「每天的路線」
- 預計：Phase 3

### B2 站可以沒有時間
- 現況：新增自訂地點或編輯地點時，可以選了天數卻不填時間；編輯共用行程的地點時清空時間，會讓它變成沒有時間（文字欄位清空則是沿用原本內容）。沒有時間的站排在當天最後，時間軸顯示「自訂行程」
- 出處：`app.js:809`、`app.js:899-917`、`app.js:1112`
- 規格：itinerary「站一定有時間」
- 預計：Phase 3

### B3 被刪除的地點無法單獨還原
- 現況：刪除共用行程裡的地點後，畫面上就找不到它，只能用「全部還原」救回，會把其他本機修改一起還原
- 出處：`app.js:359`、`app.js:951-960`
- 規格：local-edits「刪除與還原」
- 預計：Phase 3（例如在美食景點清單標示「已刪除」，點進去可以還原）

### B4 詳細資訊的「起點」用語
- 現況：詳細資訊寫「交通路線 (起點: 〇〇)」，〇〇其實是前一站，跟名詞表的「起點」意思衝突
- 出處：`app.js:1519`、`app.js:1537`
- 規格：transit「沿用交通說明的條件」
- 預計：下次改畫面時，改成「從〇〇出發」

### B5 起點不在當天第一站時，時間軸與地圖不一致
- 現況：時間軸把被標成起點的站一律當成沒有前一站；地圖只有在它是當天第一站時才從它開始畫。共用行程有資料檢查擋住，但本機修改可以把起點移到較晚的時間
- 出處：`app.js:233`、`app.js:1376`
- 規格：transit「時間軸與地圖用同一套起點規則」
- 預計：Phase 3

### B6 畫面用語跟名詞表不一致
- 現況：「還原成原始資料」「還原成原始行程」應為「共用行程」；沒有時間的站顯示「自訂行程」（隨 B2 一起消失）
- 出處：`app.js:940`、`app.js:952`、`app.js:1112`
- 預計：下次改畫面時

### B7 照片欄位的說明文字不正確
- 現況：新增自訂地點表單寫「可留空，會自動載入分類預設圖」，實際上所有類別都顯示同一張預設圖
- 出處：`index.html:460`
- 預計：下次改畫面時

### B8 網頁標題的預設文字
- 現況：載入資料前，標題顯示「東京跨年預備行」，但旅程是 12/9～12/14，不是跨年
- 出處：`index.html:63`
- 預計：小修正，下次改網站時順便改

## 沒有後端的將就做法

### B9 本機修改只存在自己的手機
- 現況：旅伴在 App 裡的修改只存在自己的手機，要改共用行程得把本次變更交給主揪，再由 Claude 改 `data.js`
- 規格：local-edits「只存在這支手機」
- 預計：Phase 4 決定後端時，一併決定要不要保留「只有自己看得到的修改」

## 只適用這趟東京行的寫法

### B10 寫死在程式或網頁裡的旅程內容
- 現況：
  - 資料檢查的座標限定日本範圍（`tools/check-data.js:77`）
  - 飯店的 id 寫死在程式裡（`app.js:44`），`check-data.js` 從 `app.js` 讀出來
  - 行前清單項目、旅遊建議、交通票券的文字寫死在 `index.html`，句子裡提到的天數不會自動更新
  - 網頁說明（meta description）寫死日期（`index.html:9`、`index.html:15`）
  - 出發日與起飛時間的預設值寫死在 `app.js`（`app.js:212`、`app.js:477-478`）
  - 預算計算機的舊版預設值（`app.js:1713`）
- 預計：做多趟旅程時一起處理

## 還沒決定的設計問題

### D1 路段
- 問題：交通說明現在寫在「到達的那一站」上，描述從前一站怎麼過來，所以移動地點時前後站都要改。要不要改成獨立的「路段」（A 站 → B 站）？
- 預計：Phase 3 設計資料格式時決定

### D2 站是一次造訪
- 問題：名詞表已定義「站＝一次造訪」，同一個地點可以是不同天的站；現在的資料一個地點只能排一天（成田機場是建了兩個地點）
- 預計：Phase 3 設計資料格式時照這個定義做

### D3 多間飯店時的起點
- 問題：旅程中換飯店（例如前兩晚東京、後兩晚大阪）時，每天的起點是哪一間
- 預計：做多趟旅程時決定
